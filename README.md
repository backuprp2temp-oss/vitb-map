# VITmap Bhopal 🎓

An interactive, fully 3D digital map and smart navigation platform for **VIT Bhopal University** (Kothri Kalan, Sehore district, Madhya Pradesh). Dark-themed, mobile-friendly, and built around real campus geography.

> Inspired by the VITmap concept for VIT Vellore (https://vit-map.vercel.app/) — rebuilt from scratch for VIT Bhopal's actual campus. No Vellore geometry, coordinates, or campus data is used.

## Quick start

```bash
npm install
npm run dev        # → http://localhost:5173
```

```bash
npm test           # run the automated test suite (vitest)
npm run build      # type-check + production build → dist/
npm run preview    # serve the production build locally
npm run import:osm # re-fetch OpenStreetMap data and rebuild the datasets
```

No API keys, no login, no backend required — the app is fully functional offline after install.

## What it does

- **Interactive 3D campus** — real OpenStreetMap footprints extruded by height: academic blocks (AB1, AB2, Lab Complex, Architecture Building), hostel blocks, mess halls, sports courts, ponds, roads and paths. Rotate, zoom, pan, top-down 2D view, fullscreen, camera reset.
- **Smart search** — MiniSearch-powered fuzzy search over names, common names, aliases and categories: "Library", "Boys hostel", "Mess", "ATM", "cse lab", "mph". Room-number queries return an honest empty result (room-level data does not exist on campus yet).
- **Walking navigation** — pedestrian routes over a graph built from mapped roads/paths (Dijkstra). Distance from real route geometry, time from a documented 1.4 m/s walking speed, turn-by-turn steps, graceful "no route" handling, origin from any place / map point / browser geolocation.
- **What's Nearby?** — nearest ATM, mess, cafe, medical, bicycle parking, parcel point and more for any selected place, ordered by walking distance (straight-line clearly labelled when routing fails).
- **Mess menus** — honest "Menu unavailable" state by default; administrator menu editor (weekly templates + dated menus) stored in localStorage; adapter interface ready for a future authorized campus API (`VITE_MENU_API_URL`).
- **Favorites** — star places (persisted in localStorage), quick-access chips, prominence in search.
- **Feedback** — report missing/incorrect locations; structured report is copyable/emailable for review before being added to trusted data.
- **Category filters** — toggle academic/hostel/food/sports/service/medical/study/event layers on the map.

## Architecture

| Concern | Choice | Why |
| --- | --- | --- |
| 3D rendering | **React Three Fiber + drei (three.js)** | Custom extruded geometry from real footprints, full control of the dark look, instanced trees, works without tile servers |
| Positioning | Local equirectangular projection (metres) around the campus centre | Campus spans ~1.5 km — sub-metre accuracy, keeps the scene in plain metric units |
| Search | **MiniSearch** (local index) | Small, fast, fuzzy + prefix + alias support, no network |
| Routing | Custom graph (Dijkstra) over walkable OSM highways | Real pedestrian paths where mapped; honest unreachable handling |
| State | **zustand** (persist middleware) | Favorites/category visibility in localStorage, tiny API |
| UI | **React + Tailwind CSS** | Mobile-first, dark glass panels, bottom sheets |
| Data | Static JSON generated by an OSM import pipeline | Versionable, diffable, no runtime API dependency |

## Data sources & attribution

1. **OpenStreetMap via the Overpass API** — building footprints, roads, paths, hostels, food courts, sports facilities, water bodies. Map data © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright), ODbL.
2. **VIT Bhopal official site** (vitbhopal.ac.in) — verification that the Central Library, Health Center, in-hostel ATMs and gyms exist.
3. **Manual curation** (`data/manual-overrides.json`) — friendly names, aliases, menu identifiers, estimated positions for facilities whose exact location is not publicly mapped.

### Verification levels

Every place carries a verification level shown in the UI:

- **Verified** — official source (survey-grade).
- **Community data** — OpenStreetMap community mapping (names/geometry); reliable but crowd-sourced.
- **Estimated location** — the facility exists (official confirmation) but its position is an estimate. Shown with an amber badge and an explanatory note.

### Honest limitations

Documented, not hidden:

- **Room-level data does not exist.** Floor directories and indoor navigation are intentionally not faked. The data model supports floors/rooms — admins can add them via `manual-overrides.json` (or a future Supabase backend).
- **Building heights are estimates** (3.2 m per level) unless OSM published `building:levels`.
- **Hostel block names are estimates** — OSM maps most hostel buildings unnamed; block letters/numbers need community verification (use the feedback button).
- **The exact pedestrian gate position is unmapped** in OSM; the "VIT Bhopal Main Campus" point sits on the highway frontage.
- **Mess menus are unavailable by default** — VIT Bhopal publishes no machine-readable menu; the app never shows invented menus.
- **No railway layer** — the nearest stations (Sehore, Phanda, Pachawan) are 20+ km away, so a railway layer is not geographically relevant to the campus. Nearby transport connections (SH-28 Bhopal–Indore highway frontage) are mapped instead.
- **Routes/turn instructions are approximate** — the graph carries few street names; distances and the 1.4 m/s speed assumption are stated in the UI.

## Adding / updating campus locations

### Curate without code rewrites

Edit `data/manual-overrides.json`:

```jsonc
{
  "override": [
    {
      "match": { "osmType": "way", "osmId": 1120857899 },
      "name": "Lab Complex",
      "category": "academic",
      "aliases": ["cse lab"],
      "floors": [{ "level": 0, "note": "Computer labs" }]
    }
  ],
  "add": [
    {
      "id": "my-new-poi",
      "name": "Photocopy Shop",
      "category": "service",
      "subcategory": "shop",
      "lat": 23.0745, "lon": 76.8505,
      "verification": "community"
    }
  ]
}
```

Then `npm run import:osm` (uses the cached raw response by default when re-running; delete `data/raw/` to force a fresh Overpass fetch). Curated entries survive upstream changes — the pipeline merges overrides on top of fresh OSM data, detects duplicates, and records sources/timestamps.

### Re-fetch from OpenStreetMap

```bash
rm -rf data/raw
npm run import:osm
```

The pipeline fetches buildings, highways, amenities, leisure, natural and landuse features, keeps the built campus + surrounding context, normalizes everything into `src/data/campus/*.json`, computes entrances (nearest walkable vertex, labelled estimated), attaches POIs to buildings by point-in-polygon, and reports duplicate warnings.

### Wire a real menu source

Set `VITE_MENU_API_URL` to an authorized endpoint exposing `GET /menus?outlet=<menuId>&date=YYYY-MM-DD` returning `{ sections: [{ key, label, timing?, items }], updatedAt }`. The UI automatically prefers the remote adapter; local admin menus and the "unavailable" state remain as fallbacks. See `.env.example`.

## Environment variables

All optional — see `.env.example`:

- `VITE_OVERPASS_URL` — Overpass endpoint for the import script (default: public API, no key).
- `VITE_FEEDBACK_EMAIL` — contact address for the feedback dialog.
- `VITE_MENU_API_URL` — optional future menu backend.

## Performance notes

- Buildings, paths, areas and trees are merged/batched geometries; trees use **InstancedMesh** with deterministic scatter.
- Tree count and pixel ratio scale down on coarse-pointer/small-screen devices; shadows are disabled on small touch devices.
- three.js/fiber/drei are split into a dedicated chunk (lazy-loaded by the browser's module loader).
- Respect `prefers-reduced-motion`; WebGL-unavailable browsers get a functional fallback (search, details, routing panels still work).
- Profiling was done in development on desktop; per-device frame-rate claims are intentionally omitted — set a target after measuring on representative student hardware.

## Deployment

The build is fully static — deploy `dist/` to Vercel, Netlify, GitHub Pages or any static host:

```bash
npm run build
npx vercel deploy --prod   # or: npx netlify deploy --prod --dir=dist
```

No server-side secrets are used; all env vars are optional build-time configuration.

## Testing

```bash
npm test
```

- `src/tests/search.test.ts` — exact names, aliases ("cse lab", "mph", "bhm"), spelling variations ("medical centre"/"center"), partial matches, honest empty results for room numbers and gibberish.
- `src/tests/routing.test.ts` — real routes between connected places, distance/time consistency with the walking-speed assumption, bidirectional routing, snapping, unreachable handling, formatters.
- `src/tests/data.test.ts` — schema integrity, unique ids, footprint/height validity, building attachments, search indexing, walkable paths, area kinds, menu-outlet sync, honest verification statuses.
